## 1. 为什么需要函数式编程

Java 8 引入 Lambda 与 Stream，核心动机是：

1. **更简洁地表达「做什么」**，而不是「怎么做」（声明式 vs 命令式）。
2. **更好地利用多核**：`parallelStream()` 与 `CompletableFuture` 降低并发样板代码。
3. **减少可变状态**：不可变数据 + 纯函数更易测试、更少线程问题。

函数式风格不等于「不用 for 循环」。在热路径、简单遍历、需要 `break/continue` 时，传统循环往往更清晰。原则是：**集合转换、过滤、聚合用 Stream；副作用、索引访问、性能敏感循环用 for**。

## 2. Lambda 表达式

### 2.1 基本语法

```java
// 无参
Runnable r = () -> System.out.println("run");

// 单参（可省略括号与类型）
Consumer<String> log = msg -> System.out.println(msg);

// 多参
BinaryOperator<Integer> add = (a, b) -> a + b;

// 多语句需花括号，单表达式可省略 return
Function<String, Integer> len = s -> {
    Objects.requireNonNull(s);
    return s.length();
};
```

### 2.2 与匿名内部类的区别

| 对比项 | 匿名内部类 | Lambda |
|--------|-----------|--------|
| `this` 指向 | 匿名类自身 | 外围类 |
| 能否访问非 final 局部变量 | 需 effectively final | 同样需 effectively final |
| 字节码 | 生成独立 `.class` | 使用 `invokedynamic`，更轻量 |
| 适用 | 任意接口/类 | **仅函数式接口** |

```java
public class LambdaDemo {
    private String prefix = "LOG: ";

    void demo() {
        // Lambda 中 this 是 LambdaDemo 实例
        Runnable r = () -> System.out.println(this.prefix);

        // 匿名类中 this 是 Runnable 实例
        Runnable r2 = new Runnable() {
            @Override
            public void run() {
                // System.out.println(this); // Runnable 匿名类
            }
        };
    }
}
```

### 2.3 变量捕获（effectively final）

```java
int base = 10;
// base = 20; // 若修改，下面 Lambda 编译失败
IntUnaryOperator inc = x -> x + base;
```

Lambda 不能修改外围局部变量，避免并发与生命周期歧义。需要「可变计数器」时用 `AtomicInteger` 或 `int[]`（不推荐后者，仅作了解）。

### 2.4 实战：排序与比较器

```java
record Order(Long id, String customer, BigDecimal amount, LocalDateTime createdAt) {}

List<Order> orders = loadOrders();

// 多字段排序
orders.sort(
    Comparator.comparing(Order::customer)
        .thenComparing(Order::createdAt, Comparator.reverseOrder())
        .thenComparing(Order::amount)
);

// 自定义 Comparator.comparing 提取键
Map<String, BigDecimal> sumByCustomer = orders.stream()
    .collect(Collectors.groupingBy(
        Order::customer,
        Collectors.mapping(Order::amount, Collectors.reducing(BigDecimal.ZERO, BigDecimal::add))
    ));
```

## 3. 函数式接口（Functional Interface）

### 3.1 定义与 `@FunctionalInterface`

只有一个**抽象方法**的接口；可有 `default`/`static` 方法。

```java
@FunctionalInterface
public interface EventHandler<T> {
    void handle(T event);

    default void onError(Exception e) {
        System.err.println("handler error: " + e.getMessage());
    }
}
```

### 3.2 JDK 内置四大核心接口

| 接口 | 方法 | 典型用途 |
|------|------|----------|
| `Predicate<T>` | `boolean test(T)` | 过滤 `filter` |
| `Function<T,R>` | `R apply(T)` | 映射 `map` |
| `Consumer<T>` | `void accept(T)` | 消费 `forEach` |
| `Supplier<T>` | `T get()` | 延迟提供 `orElseGet` |

```java
Predicate<String> notBlank = s -> s != null && !s.isBlank();
Function<String, String> trimUpper = s -> s.trim().toUpperCase(Locale.ROOT);
Consumer<String> printer = System.out::println;
Supplier<Instant> now = Instant::now;
```

### 3.3 原始类型特化（避免装箱）

```java
IntPredicate isEven = n -> n % 2 == 0;
IntUnaryOperator square = n -> n * n;
ToIntFunction<String> length = String::length;

IntStream.rangeClosed(1, 10)
    .filter(isEven)
    .map(square)
    .forEach(System.out::println);
```

### 3.4 组合与短路

```java
Predicate<String> isLong = s -> s.length() > 5;
Predicate<String> startsWithA = s -> s.startsWith("A");

Predicate<String> combined = isLong.and(startsWithA).negate();

Function<Integer, Integer> times2 = x -> x * 2;
Function<Integer, Integer> plus1 = x -> x + 1;
Function<Integer, Integer> times2ThenPlus1 = times2.andThen(plus1); // x -> x*2+1
```

### 3.5 自定义函数式接口实战

```java
@FunctionalInterface
public interface RetryableSupplier<T> {
    T get() throws Exception;

    static <T> T execute(RetryableSupplier<T> supplier, int maxAttempts) throws Exception {
        Exception last = null;
        for (int i = 1; i <= maxAttempts; i++) {
            try {
                return supplier.get();
            } catch (Exception e) {
                last = e;
                if (i == maxAttempts) break;
                Thread.sleep(100L * i);
            }
        }
        throw last;
    }
}

// 使用
String body = RetryableSupplier.execute(() -> httpGet("https://api.example.com/health"), 3);
```

## 4. 方法引用（Method Reference）

语法：`类::方法` 或 `实例::方法`。是 Lambda 的简写，当 Lambda 仅调用已有方法时优先使用方法引用。

### 4.1 四种形式

```java
// 1. 静态方法引用
Function<String, Integer> parseInt = Integer::parseInt;

// 2. 实例方法引用（特定类型）
Function<String, String> upper = String::toUpperCase;

// 3. 特定对象的实例方法
PrintStream out = System.out;
Consumer<String> print = out::println;

// 4. 构造方法引用
Supplier<List<String>> listFactory = ArrayList::new;
Function<String, User> userFactory = User::new; // 等价于 s -> new User(s)
```

### 4.2 与 Stream 结合

```java
List<String> names = List.of("alice", "bob", "charlie");

List<String> upper = names.stream()
    .map(String::toUpperCase)
    .toList(); // Java 16+ 不可变列表

Map<String, Integer> nameLen = names.stream()
    .collect(Collectors.toMap(Function.identity(), String::length));
```

### 4.3 注意：重载与类型推断

```java
// 构造方法引用需上下文推断参数类型
BiFunction<String, Integer, User> ctor = User::new; // User(String name, int age)
```

## 5. Stream API 深入

### 5.1 创建 Stream

```java
// 集合
Stream<String> s1 = List.of("a", "b").stream();

// 数组
IntStream s2 = Arrays.stream(new int[]{1, 2, 3});

// 无限流 + limit
Stream<Integer> s3 = Stream.iterate(0, n -> n + 1).limit(10);

// Java 9+ iterate 带谓词
Stream<Integer> s4 = Stream.iterate(0, n -> n < 100, n -> n + 2);

// 拼接
Stream<String> merged = Stream.concat(Stream.of("x"), Stream.of("y"));

// 文件行（NIO）
try (Stream<String> lines = Files.lines(Path.of("app.log"))) {
    lines.filter(l -> l.contains("ERROR")).forEach(System.out::println);
}
```

### 5.2 中间操作 vs 终端操作

- **中间操作**（`filter`、`map`、`sorted`…）惰性求值，返回新 Stream。
- **终端操作**（`collect`、`reduce`、`forEach`、`count`…）触发实际计算。

```java
// 错误：没有终端操作，什么都不会执行
Stream.of(1, 2, 3).map(n -> n * 2);

// 正确
List<Integer> doubled = Stream.of(1, 2, 3).map(n -> n * 2).toList();
```

### 5.3 map / filter / distinct / sorted

```java
record Product(String sku, String category, BigDecimal price, boolean onSale) {}

List<Product> products = repo.findAll();

List<String> topSkus = products.stream()
    .filter(Product::onSale)
    .filter(p -> p.price().compareTo(new BigDecimal("100")) < 0)
    .sorted(Comparator.comparing(Product::price).reversed())
    .map(Product::sku)
    .distinct()
    .limit(20)
    .toList();
```

### 5.4 flatMap：展平嵌套结构

```java
List<List<String>> nested = List.of(
    List.of("a", "b"),
    List.of("c")
);

List<String> flat = nested.stream()
    .flatMap(Collection::stream)
    .toList(); // [a, b, c]

// 实战：订单行 -> 所有商品 ID
List<Long> productIds = orders.stream()
    .flatMap(o -> o.getLines().stream())
    .map(OrderLine::productId)
    .distinct()
    .toList();

// Optional 场景
Optional<String> city = Optional.of(user)
    .flatMap(User::getAddress)
    .flatMap(Address::getCity);
```

### 5.5 reduce：聚合

```java
// 求和
int sum = Stream.of(1, 2, 3, 4).reduce(0, Integer::sum);

// 找最大值
Optional<Integer> max = Stream.of(3, 1, 4).reduce(Integer::max);

// 字符串拼接
String joined = Stream.of("Java", "Stream", "API")
    .reduce("", (a, b) -> a.isEmpty() ? b : a + ", " + b);

// 带组合器（并行 reduce 需要）
int parallelSum = Stream.of(1, 2, 3, 4)
    .parallel()
    .reduce(0, Integer::sum, Integer::sum);
```

### 5.6 collect：可变归约

```java
// toList / toSet（Java 16+ 不可变；需要可变用 toCollection）
List<String> list = stream.collect(Collectors.toList());

// toMap —— 注意 key 冲突
Map<Long, String> idToName = users.stream()
    .collect(Collectors.toMap(User::id, User::name, (a, b) -> a)); // 合并函数

// partitioningBy：布尔分组
Map<Boolean, List<Order>> paidMap = orders.stream()
    .collect(Collectors.partitioningBy(Order::isPaid));

// groupingBy：多级分组
Map<String, Map<Boolean, Long>> stats = orders.stream()
    .collect(Collectors.groupingBy(
        Order::customer,
        Collectors.groupingBy(Order::isPaid, Collectors.counting())
    ));

// joining
String csv = names.stream().collect(Collectors.joining(",", "[", "]"));

// summarizing
IntSummaryStatistics stats2 = ages.stream().collect(Collectors.summarizingInt(Integer::intValue));
```

### 5.7 自定义 Collector

```java
public record MoneySummary(BigDecimal total, long count, BigDecimal max) {}

Collector<Order, ?, MoneySummary> moneyCollector = Collector.of(
    () -> new Object[] { BigDecimal.ZERO, 0L, BigDecimal.ZERO }, // 累加器 [sum, count, max]
    (acc, order) -> {
        BigDecimal sum = (BigDecimal) acc[0];
        long count = (long) acc[1];
        BigDecimal max = (BigDecimal) acc[2];
        acc[0] = sum.add(order.amount());
        acc[1] = count + 1;
        acc[2] = max.max(order.amount());
    },
    (a, b) -> {
        a[0] = ((BigDecimal) a[0]).add((BigDecimal) b[0]);
        a[1] = (long) a[1] + (long) b[1];
        a[2] = ((BigDecimal) a[2]).max((BigDecimal) b[2]);
        return a;
    },
    acc -> new MoneySummary((BigDecimal) acc[0], (long) acc[1], (BigDecimal) acc[2])
);

MoneySummary summary = orders.stream().collect(moneyCollector);
```

更复杂的场景可用 `Collector.of` 四参数 + `Characteristics`（如 `UNORDERED`、`CONCURRENT`）。

### 5.8 peek：调试（勿用于业务副作用）

```java
List<String> result = Stream.of("a", "bb", "ccc")
    .peek(s -> log.debug("before filter: {}", s))
    .filter(s -> s.length() > 1)
    .peek(s -> log.debug("after filter: {}", s))
    .toList();
```

## 6. 并行流（Parallel Stream）

```java
long count = hugeList.parallelStream()
    .filter(this::isValid)
    .count();
```

### 6.1 适用条件

- 数据量大（通常 **数万以上** 才有收益）。
- 计算密集、无共享可变状态。
- 源可高效拆分（`ArrayList` 好，`LinkedList` 差）。

### 6.2 常见陷阱

```java
// ❌ 错误：并行 + 修改外部集合
List<Integer> bad = new ArrayList<>();
IntStream.range(0, 1000).parallel().forEach(bad::add); // 线程不安全

// ✅ 正确：collect
List<Integer> good = IntStream.range(0, 1000).parallel().boxed().toList();

// ❌ 错误：并行 + synchronized 块 -> 可能比串行更慢
// ❌ 错误：依赖 encounter order 的 forEachOrdered 在并行下性能差

// ❌ 在 ForkJoinPool.commonPool() 里做阻塞 IO
urls.parallelStream().forEach(this::blockingHttpGet); // 阻塞公共池，拖垮全局
```

**阻塞 IO 并行**应使用专用线程池 + `CompletableFuture`，而非 `parallelStream()`。

### 6.3 自定义 ForkJoinPool（高级）

```java
ForkJoinPool customPool = new ForkJoinPool(4);
try {
    int sum = customPool.submit(() ->
        IntStream.range(0, 1_000_000).parallel().sum()
    ).get();
} finally {
    customPool.shutdown();
}
```

## 7. Optional 深入

`Optional<T>` 表示「可能有值」，用于**返回值**，不要用于字段、方法参数、集合元素。

### 7.1 创建

```java
Optional<String> empty = Optional.empty();
Optional<String> of = Optional.of("x");           // null 抛 NPE
Optional<String> ofNullable = Optional.ofNullable(maybeNull());
```

### 7.2 消费与转换

```java
Optional<User> userOpt = userRepo.findById(id);

// 有值才执行
userOpt.ifPresent(u -> log.info("found {}", u.name()));

// 映射
Optional<String> email = userOpt.map(User::email);

// 展平
Optional<String> city = userOpt
    .flatMap(User::address)
    .flatMap(Address::city);

// 默认值
String name = userOpt.map(User::name).orElse("匿名");
String name2 = userOpt.map(User::name).orElseGet(() -> loadDefaultName());
String name3 = userOpt.map(User::name).orElseThrow(() -> new NotFoundException(id));

// Java 9+
userOpt.ifPresentOrElse(
    u -> sendMail(u.email()),
    () -> log.warn("no user {}", id)
);

// Java 11：空则返回 empty，否则 Optional.of(result)
Optional<String> upper = userOpt.flatMap(u -> Optional.ofNullable(u.name()).map(String::toUpperCase));
```

### 7.3 反模式

```java
// ❌ 不要用 Optional 做参数
void update(Optional<String> name) { }

// ❌ 不要 get() 而不检查
User u = userOpt.get(); // 可能 NoSuchElementException

// ❌ 不要用 isPresent + get
if (userOpt.isPresent()) {
    doSomething(userOpt.get());
}
// ✅ 用 ifPresent / map / orElseThrow

// ❌ 集合元素不要包 Optional
List<Optional<User>> users;
```

### 7.4 实战：链式查询

```java
public String resolveDisplayName(Long userId) {
    return userRepo.findById(userId)
        .flatMap(User::profile)
        .map(Profile::nickname)
        .filter(n -> !n.isBlank())
        .or(() -> userRepo.findById(userId).map(User::username))
        .orElse("访客");
}
```

## 8. CompletableFuture 基础

用于异步组合，弥补 `Future.get()` 阻塞与难以链式编排的不足。

### 8.1 创建与获取结果

```java
ExecutorService pool = Executors.newFixedThreadPool(8);

CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    return fetchFromRemote();
}, pool);

// 阻塞获取
String result = future.join(); //  unchecked
// String result = future.get(3, TimeUnit.SECONDS);
```

### 8.2 链式转换

```java
CompletableFuture<Integer> lenFuture = CompletableFuture
    .supplyAsync(() -> httpGet("https://api.example.com/user/1"))
    .thenApply(JSON::parseObject)
    .thenApply(json -> json.getString("name"))
    .thenApply(String::length);

// 异步转换（在另一线程执行 apply）
CompletableFuture<String> async = future.thenApplyAsync(String::toUpperCase, pool);
```

### 8.3 thenCompose：展平嵌套 Future

```java
CompletableFuture<Order> orderFuture = CompletableFuture
    .supplyAsync(() -> userId)
    .thenCompose(id -> orderService.findLatestAsync(id)); // 避免 CompletableFuture<CompletableFuture<Order>>
```

### 8.4 组合多个任务

```java
CompletableFuture<User> userF = userService.getAsync(userId);
CompletableFuture<List<Order>> ordersF = orderService.listAsync(userId);

CompletableFuture<UserDashboard> dashboardF = userF.thenCombine(ordersF, UserDashboard::new);

// allOf / anyOf
CompletableFuture<Void> all = CompletableFuture.allOf(userF, ordersF);
all.join();
User user = userF.join();
```

### 8.5 异常处理

```java
CompletableFuture<String> f = CompletableFuture
    .supplyAsync(() -> risky())
    .handle((result, ex) -> {
        if (ex != null) {
            log.error("failed", ex);
            return "fallback";
        }
        return result;
    })
    .exceptionally(ex -> "fallback"); // 仅异常分支

// 完成时消费（类似 finally）
f.whenComplete((r, ex) -> metrics.record(ex == null));
```

### 8.6 与虚拟线程（Java 21）

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    CompletableFuture<String> f1 = CompletableFuture.supplyAsync(this::ioTask1, executor);
    CompletableFuture<String> f2 = CompletableFuture.supplyAsync(this::ioTask2, executor);
    String combined = f1.thenCombine(f2, (a, b) -> a + b).join();
}
```

IO 密集场景优先虚拟线程执行器，而非 `parallelStream()`。

## 9. 副作用与纯函数：工程实践

### 9.1 什么是副作用

在 Stream 中修改外部变量、写数据库、发 HTTP 请求都属于副作用。中间操作应尽量无副作用。

```java
// ❌
AtomicInteger counter = new AtomicInteger();
list.stream().filter(x -> { counter.incrementAndGet(); return true; });

// ✅ 用 count()
long cnt = list.stream().filter(predicate).count();
```

### 9.2 forEach 仅用于终端消费

```java
// 批量发通知：可以 forEach，但注意事务边界
recipients.stream()
    .filter(User::notifyEnabled)
    .forEach(user -> notificationService.send(user)); // 副作用放终端
```

### 9.3 不可变优先

```java
List<String> transformed = source.stream()
    .map(String::trim)
    .filter(s -> !s.isEmpty())
    .toList(); // 新列表，不修改 source
```

## 10. Java 21 Gatherers 简介

Java 21 预览/标准 API 中的 **Gatherers** 允许编写**自定义中间操作**（类似 `filter`/`map` 但可维护状态）。

```java
import java.util.stream.Gatherers;

// 滑动窗口（示例：每 3 个元素一组）
List<List<Integer>> windows = Stream.of(1, 2, 3, 4, 5, 6, 7)
    .gather(Gatherers.windowFixed(3))
    .toList();
// [[1,2,3], [4,5,6], [7]]

// fold：有状态的聚合中间步骤
Stream<String> folded = Stream.of("a", "b", "c", "d")
    .gather(Gatherers.fold(
        () -> new StringBuilder(),
        (sb, s) -> sb.append(s).append("-"),
        sb -> sb.toString()
    ));
```

Gatherers 适合：窗口、批处理、去重（带状态）、复杂限流。一般业务用内置 `collect`/`reduce` 即可，遇到「标准中间操作表达不了」时再查 Gatherers。

## 11. 综合实战：订单报表

```java
public class OrderReportService {

    public record ReportRow(String category, long orderCount, BigDecimal totalAmount) {}

    public List<ReportRow> buildReport(List<Order> orders, YearMonth month) {
        return orders.stream()
            .filter(o -> YearMonth.from(o.createdAt()).equals(month))
            .filter(o -> o.status() != OrderStatus.CANCELLED)
            .flatMap(o -> o.lines().stream()
                .map(line -> new AbstractMap.SimpleEntry<>(line.category(), o.id(), line.amount())))
            .collect(Collectors.groupingBy(
                Map.Entry::getKey,
                Collectors.collectingAndThen(
                    Collectors.toList(),
                    entries -> {
                        long distinctOrders = entries.stream()
                            .map(e -> e.getValue())
                            .distinct()
                            .count();
                        BigDecimal total = entries.stream()
                            .map(e -> (BigDecimal) e.getValue())
                            .reduce(BigDecimal.ZERO, BigDecimal::add);
                        return new ReportRow(entries.get(0).getKey(), distinctOrders, total);
                    }
                )
            ))
            .values().stream()
            .sorted(Comparator.comparing(ReportRow::totalAmount).reversed())
            .toList();
    }
}
```

## 12. 性能与选型速查

| 场景 | 推荐 |
|------|------|
| 集合过滤/映射/分组 | `stream()` |
| 大数据 CPU 计算 | `parallelStream()` + 无共享状态 |
| 阻塞 IO 并发 | `CompletableFuture` + 虚拟线程池 |
| 可能为空的单值返回 | `Optional` |
| 简单遍历、早退 | 增强 `for` 或 `forEach` |
| 索引访问 | 传统 `for` |
| 自定义中间操作（JDK 21） | `Gatherers` |

## 13. 常见面试题速记

1. **Stream 惰性？** 中间操作惰性，终端操作触发。
2. **`map` vs `flatMap`？** `map` 一对一；`flatMap` 一对多再展平。
3. **`reduce` vs `collect`？** `reduce` 不可变归约；`collect` 可变容器（更灵活）。
4. **Optional 设计目的？** 显式表达缺失值，避免 NPE；不是通用容器。
5. **parallelStream 线程池？** 默认 `ForkJoinPool.commonPool()`，大小 ≈ CPU 核数 - 1。

## 14. 小结

函数式 API 的核心是：**用声明式管道处理数据、用 Optional 表达缺失、用 CompletableFuture 编排异步**。写好 Java 函数式代码的关键不是「处处 Stream」，而是：

1. 保持管道**无副作用**；
2. 并行前评估**拆分成本与线程安全**；
3. Optional 只作**返回值语义**；
4. IO 并发交给**专用执行器或虚拟线程**。

结合 Java 17 的 `toList()`、Records，以及 Java 21 的 Gatherers 与虚拟线程，可以在保持可读性的同时获得更好的并发与表达能力。
